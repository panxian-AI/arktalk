# ArkTalk —— 完全独立的端对端聊天软件

> 定位：**一套和 QQ 完全不同的聊天软件，与 QQ 没有任何数据沟通**。
> 账号、联系人、群、消息全部是软件自己的，数据全部留在本机。
> 对外的传输层是 **P2P 端对端直连**（自研 PeerLink 内核，WS 直连 + 离线发件箱），
> 跨网场景由内置 OpenP2P 提供端口映射（阶段 2）。
>
> 同时它**可以像 QQ 一样被 SnowLuma 注入**：作为宿主进程接受 SnowLuma 注入
> （配置 `snowluma.enabled=true` 时连接其 OneBot v11 通道，只收不发；发送一律走 P2P）。
>
> **账号认设备，无需注册**：首次运行自动生成本机账号 ID；昵称/头像在"我的账号"
> 里手动设置。**联系人手动添加**（对方账号 + 连接地址）；非联系人的消息一律忽略。
> **不含 AI**。

```
ArkTalk 设备 A ←── PeerLink（WS 直连 / OpenP2P 映射）──→ ArkTalk 设备 B
        │                                                        │
   本地桥 127.0.0.1:3020（界面服务 + 本机落盘）              同左
   P2P 内核 0.0.0.0:3021（接受对方设备连入）
```

## 运行

```
cd arktalk
npm install
npm run app        # 桌面窗口（Electron）：自动拉起本地桥，关窗即退出
npm start          # 浏览器模式：只起本地桥，手动开 http://127.0.0.1:3020
```

- 自检（双实例对通，零外部依赖）：`npm run selftest`，22 项（含文件传输回归）。

## 两台设备怎么聊起来

1. 两台设备都跑 ArkTalk，各自在"我的账号"里看自己的**账号 ID**（数字）
2. 互相**加联系人**：导航栏 👥 → 输对方账号 + 备注 + **对方连接地址**（`IP:3021`；
   局域网直接填对方内网 IP；跨网等 OpenP2P 阶段填映射地址）
3. 一方发消息即建立 P2P 直连；**对方离线时消息入发件箱，可达后自动补发**（已 ack 确认）
4. 头像/昵称经 P2P 通讯自动互报补全（备注优先，不被覆盖）

## 软件功能（全部手动操作）

| 功能 | 入口 | 说明 |
|---|---|---|
| 我的账号 | 点导航栏头像 | 昵称/头像手动设置；账号 ID 认设备不可改 |
| 加联系人 | 联系人页右上角 ＋ | 对方账号 + 备注 + 连接地址；立即私聊 |
| 建群 | 群聊页右上角 ＋ | 群名 + 勾选成员 → 本地群；消息逐成员经 P2P 直发 |
| 群成员面板 | 打开群聊 | 右侧栏：头像/昵称/在线状态，可搜索 |
| @ 群成员 | 输入框 @ | 从成员列表选，真实 at 分段 |
| 发图片 | 输入框 🖼️ | 自动压缩到 1280px 后随消息直发 |
| 引用回复 | 消息悬停「引用」 | 引用条随消息一起发送，双方都能看到引用内容 |
| 语音消息 | 输入框 🎤 | 点一下开始录音，再点发送，Esc 取消，最长 60s |
| 发文件 | 输入框 📎 | 只发卡片；**对方点「保存」才开始传输**，512KB 分块 + 6 路并发拉取，乱序重排、断点安全，落盘前逐字节校验 |
| 移除联系人 | rpc | 同时从各本地群移除该成员 |

数据全部在本机：`data/contacts.json`（账号资料/联系人/群）+ `data/messages/<chatKey>.jsonl`（消息）
+ `data/files/`（我发出的文件本体 + 登记）+ `data/downloads/（收到的文件）`。
旧版（QQ 桥时代）数据已移入 `data/_backup-qq-era-20261126/`，不参与任何逻辑。

## 与 SnowLuma 注入的关系

- 本软件是独立聊天软件，**发送不经过 QQ / 腾讯服务器**（一律 P2P）
- 被注入用法：SnowLuma 注入本进程（或本机）后，`config.json → snowluma.enabled=true`
  会连接其 OneBot v11 通道；其推来的消息按同一套规则处理（只认联系人），且**只收不发**
- 下一步（宿主能力）：提供 OneBot 兼容的内部 API，让 SnowLuma 像挂 QQ 一样挂 ArkTalk

## 边界与注意

- 界面服务只绑 127.0.0.1；P2P 内核绑 0.0.0.0:3021（要接受对方设备，这是必须的）
- 消息通道是明文 WS over LAN/隧道：跨公网走 OpenP2P 时依赖其隧道加密；
  端到端消息加密列为阶段 3（聊天码配对时一并做）
- 未知账号发来的消息不收录、不显示、不落盘
